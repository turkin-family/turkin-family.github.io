## 🏗️ 1. Общая архитектура системы

Проект построен по принципу **Single Source of Truth (SSOT)**: вся генеалогическая информация, архивные источники и связи хранятся в нормализованном JSON-виде в директории `data/`. Из этих данных автоматически генерируются:
1. **Интерактивное веб-полотно**: [`tree.html`](file:///home/slava/Documents/Родословная/tree.html) / [`index.html`](file:///home/slava/Documents/Родословная/index.html) с полнофункциональным SVG-рендером, масштабированием, карточками персон и просмотром архивных первоисточников в высоком разрешении.
2. **Файл международного стандарта**: [`rodoslovnaya_turkin.ged`](file:///home/slava/Documents/Родословная/rodoslovnaya_turkin.ged) (GEDCOM 5.5.1 UTF-8) для импорта в Desktop-программы (Древо Жизни, Gramps, MyHeritage, FamilySearch).

```

                           │          data/*.json          │
                           │  persons, families, sources,  │

                                           │

       ┌───────────────────────────┐                ┌───────────────────────────┐

```

### 2.4. `data/evidence.json` (168 записей)
Академический аппарат доказательств (связывает персону с архивным делом, номером листа и цитатой).

### 2.5. `data/collateral_turkins_1834.json` (Архив боковых семей 1834 г.)
Содержит полную машиночитаемую базу семей Туркиных Усть-Вымской волости по 8-й ревизии 1834 г., не входящих в прямую ветвь потомков Афанасия Семёновича:
* **109 персоналий**;
* **36 семейных союзов**;
* **7 архивных дел ревизии**;
* **109 связей доказательств**.
Роспись в формате Markdown представлена в [`РЕВИЗИЯ_1834_БОКОВЫЕ_СЕМЬИ_ТУРКИНЫХ.md`](file:///home/slava/Documents/Родословная/РЕВИЗИЯ_1834_БОКОВЫЕ_СЕМЬИ_ТУРКИНЫХ.md).

### 2.5. `data/calibrated_coords.json`
Координаты узлов на интерактивном полотне в декартовой системе `[X, Y]`:
* $X$: временная шкала поколений (слева направо: Gen 1 $\to$ Gen 15);
* $Y$: вертикальное позиционирование ветвей;
* **Прямая мужская линия Туркиных (Gen 1..15) зафиксирована на горизонтальной лазерной оси $Y = 800$**.

## 📐 3. Движок раскладки графа (Layout Engine)

Файл [`layout_engine.py`](file:///home/slava/Documents/Родословная/layout_engine.py) реализует:
1. **Расчет поколений**:
   * Топологическая сортировка графа от корня (`I1` — пробанд);
   * Автоматическое согласование поколений супругов и братьев/сестер;
   * Определение поколений боковых ветвей по хронологии дат рождения.
2. **Защита от наложений (Anti-Collision Guarantee)**:
   * Минимальный шаг между поколениями: $\Delta X \ge 240$ px;
   * Минимальный шаг между карточками внутри одного поколения: $\Delta Y \ge 110$ px;
   * Функция `layout_engine.validate_layout()` проводит полную попарную проверку геометрических пересечений перед генерацией HTML.

## ⚡ 4. Валидация и тестирование интерфейса

Проект оснащен трехуровневой системой верификации:
1. **Валидация ссылочной целостности**:
   * Функция `data_manager.validate_integrity()` проверяет:
     * Отсутствие "висячих" ссылок (все `husb`, `wife`, `children` существуют в `persons.json`);
     * Консистентность `famc` / `fams` во всех персоналиях;
     * Наличие источников для каждого `evidence.json`.
2. **Валидация геометрического полотна**:
   * `layout_engine.validate_layout()` гарантирует отсутствие визуальных наложений карточек.
3. **Автоматическое тестирование в браузере (Playwright)**:
   * Скрипт [`scripts/verify_ui.py`](file:///home/slava/Documents/Родословная/scripts/verify_ui.py) поднимает headless Chromium, рендерит дерево, проверяет:
     * Отсутствие ошибок в консоли JavaScript (`errors == 0`);
     * Построение 270+ кривых Безье для родственных связей (`<path>`);
     * Работоспособность модальных окон карточек персон;
     * Корректность отображения миниатюр первоисточников.
