# АРХИТЕКТУРА ПРОЕКТА, СТРУКТУРА ДАННЫХ И СБОРОЧНЫЙ ПАЙПЛАЙН

## 1. Концепция базы данных
Проект «Родословная Туркиных» построен на реляционной модели данных в формате JSON:
- `data/persons.json` — реестр персон (326 записей).
- `data/families.json` — реестр семейных союзов (117 записей).
- `data/sources.json` — каталог архивных первоисточников и PDF-альбомов (91 документ, 4 PDF).
- `data/evidence.json` — фактологические привязки событий к первоисточникам.
- `archive_catalog.py` — Python-модуль каталога (`DOCS_CATALOG`, `PDF_ALBUMS`), используемый генератором веб-приложения.

## 2. Схема сущности Person (`data/persons.json`)
```json
{
  "id": "I148",
  "name": "Алексей Григорьевич /Туркин/",
  "givn": "Алексей Григорьевич",
  "surn": "Туркин",
  "sex": "M",
  "birt_date": "ок. 1778",
  "birt_plac": "с. Коквицы, Яренский уезд, Вологодское наместничество",
  "deat_date": "1832",
  "deat_plac": "с. Коквицы, Яренский уезд, Вологодская губерния",
  "gen": 9,
  "fams": ["F141"],
  "famc": "F87",
  "source_id": "revision_1816_turkin_159",
  "notes": [
    "5-й прадед Николая Туркина.",
    "Глава выделившейся семьи № 159 в 7-й ревизии 1816 г. (лл. 352 об. – 353)."
  ]
}
```

### Ключевые требования к полям:
1. `birt_date`, `deat_date`: нормализованные строковые поля (например, `1814`, `ок. 1778`, `между 1816 и 1824`). Не использовать `birth_date`!
2. `sex`: `"M"` (мужской) или `"F"` (женский).
3. `source_id`: идентификатор архивного документа из `data/sources.json`.
4. `fams` (список семей, где персона является родителем/супругом) и `famc` (семья, где персона является ребенком) обязаны быть строго консистентны с `data/families.json`.

## 4. Пайплайн сборки проекта (`build.py`)
Единый мастер-скрипт `build.py` запускается после каждого изменения данных:
```bash
python3 build.py
```

### Этапы сборки:
1. **[1/4] Валидация базы данных (`data_manager.py`):**
   - Проверка двусторонней целостности реляционных связей `husb`/`wife`/`children` ↔ `fams`/`famc`.
   - Проверка наличия всех персон, упомянутых в семьях.
   - Проверка отсутствия висячих ссылок.
2. **[2/4] Геометрическая проверка Smart-Layout (`layout_engine.py`):**
   - Расчет декартовых координат узлов семейного древа.
   - Исключение взаимных геометрических перекрытий (Zero-Collisions).
3. **[3/4] Экспорт в международный формат GEDCOM 5.5.1 (`build_genealogy.py`):**
   - Генерация файла `rodoslovnaya_turkin.ged` в кодировке UTF-8 с BOM.
4. **[4/4] Генерация веб-приложений (`generate_final_tree.py`):**
   - Компиляция интерактивного дерева: `index.html`, `tree.html`, `родословная.html`.
   - Встраивание векторных карточек, фильтров, панели поиска, вкладок архива и модального просмотрщика сканов с зумом.

## 5. Запуск локального сервера
Для визуальной проверки интерактивного интерфейса:
```bash
python3 serve.py
# или ./start_server.sh
```
Веб-интерфейс открывается на `http://localhost:8000` (или `http://localhost:8080`).
